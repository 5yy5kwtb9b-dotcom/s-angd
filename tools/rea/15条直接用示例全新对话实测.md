## 可复制的最终指令

### 1 · `inspect_packet_fields`

```text
请用 `mac_pcap` 的 `inspect_packet_fields` 查找以 frame.len 开头的 Wireshark 字段，告诉我哪个字段表示帧长。
```

### 4 · `inspect_pcap_client`

```text
请用 `rea` 的 `inspect_pcap_client` 检查这台 Mac 上 TShark 和 capinfos 的实际路径和版本。
```

### 33 · `inspect_apktool_client`

```text
请用 `rea` 的 `inspect_apktool_client` 检查这台 Mac 实际使用的 Apktool 启动命令和版本。
```

### 35 · `inspect_adb_client`

```text
请用 `rea` 的 `inspect_adb_client` 告诉我本机 ADB 客户端的安装位置和版本。
```

### 36 · `list_adb_devices`

```text
请用 `rea` 的 `list_adb_devices` 只列出 ADB 当前可见的设备和连接状态，若列表为空就告诉我。
```

### 55 · `binary_session`

```text
请用 `rea` 的 `binary_session` 告诉我当前 REA 会话选中哪个文件、使用哪个分析后端。
```

### 68 · `list_cutter_sessions`

```text
请用 `rea` 的 `list_cutter_sessions` 列出这台 Mac 当前可发现的 Cutter 桥接会话，没有会话就报告空列表。
```

### 101 · `get_evidence_bundle`

```text
请用 `rea` 的 `get_evidence_bundle` 以摘要列出当前会话保留的证据，给出记录 ID 和产生记录的工具。
```

### 102 · `export_evidence_bundle`

```text
请用 `rea` 的 `export_evidence_bundle` 把本次测试会话的证据包保存为工作区中新文件 demo-evidence.json。
```

### 112 · `record_unknown`

```text
请用 `rea` 的 `record_unknown` 在“离线输出”领域登记中等严重度问题“相同输入是否生成相同摘要”，以受控重放的实测结果为结案依据，暂不指定环境、关联记录或后续探针，并返回问题 ID。
```

### 113 · `list_unknowns`

```text
请用 `rea` 的 `list_unknowns` 列出当前调查中严重度为中等的待解问题，最多显示十条。
```

### 118 · `guided_workflows`

```text
请用 `rea` 的 `guided_workflows` 列出 REA 内置的工作流程，并指出哪一个适合初次检查应用包。
```

### 119 · `search_guidance`

```text
请用 `rea` 的 `search_guidance` 在已安装的指南中搜索 JavaScript module，给出最相关的三个章节及定位信息。
```

### 121 · `inspect_analysis_settings`

```text
请用 `rea` 的 `inspect_analysis_settings` 查看 asar.max_header_bytes 的当前值、允许范围和生效时机。
```

### 122 · `update_analysis_settings`

```text
请用 `rea` 的 `update_analysis_settings`，按参数 {"changes":[{"setting":"asar.max_header_bytes","action":"reset"}]} 仅将本次 REA 服务的这一项恢复到启动值，报告恢复后的值和 changed 标志。
```
